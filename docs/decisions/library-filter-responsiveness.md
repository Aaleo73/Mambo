# 资料库筛选与搜索

日期：2026-10-04（筛选与搜索修复）、2026-10-05（筛选响应优化）。

## 2026-10-04：筛选与搜索修复

- **起因**：真实服务器的筛选选项接口返回 404，列表接口忽略类型、年份、分级条件。
- **筛选**：保留用完整分页推导筛选选项的做法，并在发布卡片前按元数据校验条件；原始分页游标不受过滤影响。服务器忽略筛选时，稀疏条件需要扫描多页；计数只反映已验证的结果，不提前估算总数。
- **搜索**：改为完整短语查询。媒体库分组按已加载标题的相关性排序，完整片名优先，同级保留原库顺序；移动和刷新分组时保留原来的分页观察。
- **验证**：原生 WinUI 页面在真实服务器上通过了类型筛选、类型与年代组合、下一页、重置及搜索刷新。真实电影库没有分级元数据，分级只验证了「无匹配时读完后返回空结果」，正向及组合匹配由合成回归覆盖。验证会话只在内存里，不读写用户凭据。

## 2026-10-05：筛选响应优化

针对用户反馈的筛选慢、卡住、点击无反应。

## 原因

- 兼容忽略筛选参数的服务器时，旧实现按 UI 页大小（60 条）重复扫描。每次换条件都会从头走 HTTP 分页，稀疏匹配尤其慢。
- 筛选选项接口失败后的扫描要全部结束才发布选项，已加载卡片的元数据也没有及时反映到筛选面板。
- 等待新条件时保留旧网格，却没有进行中的状态；连续点击立即创建多个请求和偏好写入。
- 年代只展开成当前已知的年份；旧偏好和大小写不同的类型可能与面板选中态不一致。

## 实现

- 保留服务器正常筛选的快速路径。收到不符合条件的条目后，才记住该账号、该资料库需要本地校验。
- 切换为不带筛选条件的共享扫描，每批最多 500 条。部分支持参数的服务器必须从无条件游标 0 重新开始，已显示条目按 ID 去重。
- 扫描保留可显示卡片所需的元数据，不下载图片。按账号、资料库、排序字段、排序方向隔离，最多保留 8 个扫描，5 分钟后新查询重新建立。完成的批次可跨条件复用；取消不发布迟到结果，也不抹掉已完成的批次。
- 筛选选项接口不可用时，共用默认排序的扫描，并逐批发布类型、年代、分级。手动刷新资料库、播放停止以及切换账号使相应缓存失效。
- 切换条件立即更新选中态和等待状态，连续点击在 200ms 内合并；取消恢复当前已显示结果对应的条件。失败保留旧结果并提供重试。新查询开始时暂停旧网格的自动翻页。
- 已加载卡片、服务器选项、已保存条件合并显示，增量更新保留已有 chip 对象。年代始终展开为完整十年，读取旧偏好时同样修正；类型和分级忽略大小写。
- 界面仅使用 Contracts，没有新增对 Core 实现的引用；新 XAML 仍在 App 内，绑定使用 x:Bind。

## 验证

- 合成 5000 条目录，唯一匹配在最后一条：首次筛选 11 次列表请求（1 次原生筛选尝试和 10 次扫描），相比旧实现约 84 次；随后更换组合条件或无匹配条件不新增列表请求。这是请求次数验证，不代表真实网络耗时。
- Core 专项测试覆盖服务器正常筛选、忽略/部分支持条件、实际批次上限、密集结果分页、尾页匹配、无匹配、刷新、取消后复用、账号/排序隔离及选项增量通知。
- `scripts/test-library-filters.ps1` 使用独立假服务进程挂载实际 LibraryPage，验证等待/取消/重试/重置按钮、连续点击合并、年代展开、旧偏好修复及离开页面取消。截图通过 RenderTargetBitmap 生成，不等同于真实鼠标和显示器人工验收。
- Debug 与 Native AOT 都通过了 15 项界面专项。

本轮没有使用真实服务器凭据；真实服务器上的首次扫描仍受目录大小、服务端批次上限与网络响应速度影响。源码与构建验证不代表已替换用户正在使用的安装版。

## 用户调整：移除重置按钮（2026-10-05）

按用户要求移除资料库页头的“重置”和空结果中的“重置筛选”按钮。清除条件使用各组的“全部”选项；等待时取消更改、失败重试继续保留。对应界面专项改为验证各组“全部”的清除行为。

调整后 Debug 与 Native AOT 的 15 项界面专项都通过。
