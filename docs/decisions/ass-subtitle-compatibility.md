# 异常内封 ASS 的自动兼容

日期：2026-10-08。

## 决定与原因

实际服务器上发现内封 ASS 的格式头包含整份带时间的对白，却缺少 `[Events]` 和事件字段定义。mpv 能列出并选中该轨道，但不会显示对白。单独修复字幕文件只能解决一个条目，因此将同类结构的自动兼容放在 `Mambo.Player` 的 libmpv 适配层。

- 只检查当前已选内封 `ass` 轨道的 `sub-ass-extradata`。没有选择字幕、手选其他轨道或正常 ASS 都沿用原生行为；不按片名、语言或“中上英下”标题判断。
- 格式头必须包含 ASS 脚本与样式声明，以及可明确解析的带时间 `Dialogue:`。只补齐缺失的事件段与字段定义，保留字体、颜色、定位、双语换行、时间和文本。已有事件字段定义、不明结构、无效时间、空文本、NUL 或超过 5 MiB 的内容不改写。
- 兼容内容通过 mpv 的 `memory://` 内存流加载。它不写入字幕库、缓存、设置或日志，不需要用户导出或拖入字幕。内存流和 `sub-add auto` 的行为依据 [mpv 内存流实现](https://github.com/mpv-player/mpv/blob/v0.41.0/stream/stream_memory.c)及[轨道操作文档](https://mpv.io/manual/stable/#track-manipulation)。
- 内部替代轨道隐藏，选择与属性通知映射回原轨道 ID。Core 继续看到原来的内封轨道、元数据和 `ff-index`，现有选轨偏好、延迟调整和 Emby 上报不使用内部轨道 ID。再次选择原轨道直接复用兼容轨道，不重复加载。
- 原生 START_FILE/END_FILE 直接登记当前条目。兼容加载的每个异步边界核对条目，迟到的新建轨道被移除；映射在新条目开始时清空。EOF 尾部事件仍使用旧映射，退出取消内部恢复后仍完整转发 SHUTDOWN。
- 兼容失败保留原生播放，不能因此中断视频。此处理仅覆盖上述可恢复结构，不是通用 ASS 修复器；外置 mpv 继续由自身处理字幕。

## 验证

- 新增 13 项回归：缺失事件段/字段定义、不同换行、带逗号的文本、无效时间、正常脚本与大小限制；合成 Matroska 中的自动恢复、原轨道身份与隐藏、切换 SRT、关闭、重新开启、暂停跳转、延迟、下一集，以及默认关闭或明确手选 SRT 时的保护。测试媒体和字幕均为自行合成，不使用真实媒体或账号数据。
- 实际服务器第 1、2 集直接加载原片并选择原来的内封 ASS，在 27 秒和 60 秒处均恢复中文、英文两行；字幕菜单数据保持两条内封轨道，内部轨道未暴露。截图检查确认中文在上、英文在下。同片 SRT 仍正常。
- `dotnet build -p:Platform=x64`：0 警告、0 错误。`dotnet test`：799 通过、0 失败、23 既有专项跳过。Native AOT 应用发布构建通过，产物在 `publish/aot`。状态见 [STATUS](../STATUS.md)。真实媒体诊断资料留在仓库外；地址和凭据不进入记录。

## 限制与未验收项

- 仅支持存在完整有效对白且缺少事件声明的内封 ASS。缺失实际对白、其他编码损坏、异常定位或特效仍需分别诊断，不能据此承诺所有损坏字幕都可恢复。
- 【需用户】真实窗口里快速选轨、关闭、恢复、连播的观感，以及不同 DPI、字体和 ASS 特效。这些不以合成测试或两集截图代替。
