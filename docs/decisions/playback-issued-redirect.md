# 保留登录服务器签发的播放跳转链接

日期：2026-10-03。

用户在正式播放器打开剧集时，收到“片源无法播放，请重试”。本机已保存会话的安全诊断确认：账号验证和继续观看查询成功；同一集的三个片源候选均由登录服务器返回 302，目标为另一个主机的下载网关。Location 查询参数中有与账号令牌相同的值。原实现的 `RemoveCopiedCredential` 将它删除，网关因此返回 HTTP 401，libmpv 以 END_FILE(error=-13) 结束，最终耗尽候选。地址、令牌、媒体 ID 和响应正文均未输出或持久化。

## 决定及信任边界

信任用户选定的登录服务器在已认证请求的响应中明确签发的完整下载 Location。保留其中原有的查询参数，即使某个参数值与账号令牌相同；客户端不自行添加认证查询参数。跨越服务器边界时仍永久清除所有认证头和 RequiredHttpHeaders，避免 ffmpeg 将这些头继续转发。返回地址不在预解析阶段继续探测；视频由播放器打开，字幕由独立下载器处理。

这修改了先前“任何跨域地址都删除相同令牌值”的策略，并非声称令牌值永远不离开登录服务器：受信任服务器明确指定的下载目标可能在 URL 中接收该值。此信任仅限于原服务器的已认证响应，不能从 CDN 的响应获得；直接传入的跨域候选也不能获得。HTTPS 到 HTTP 的降级不保留复制的账号令牌。所有地址仍限制为无内嵌用户名/密码的 HTTP(S)，原有超时、跳转次数、字幕大小及取消边界保留。完整签名查询不进行重排、增补或格式化。

视频和外挂字幕采用同一规则。此规则不扩大 API 客户端的重定向权限，不改变存储与日志的敏感数据禁令。

视频交给 mpv 后，由 mpv 处理下载站点的后续重定向；本解析器不能逐跳约束那部分查询参数。字幕下载则由本解析器继续逐跳检查，CDN 的响应不会获得原登录服务器的签发权限。这里保证的是客户端认证请求头不会被带到下载站点，不是对服务器自行签发链接中凭据流向的绝对保证。

## 验证

同一已保存会话、同一集、三个候选：修复前全部 HTTP 401 / mpv -13；修复后全部 HTTP 206 / FILE_LOADED / PLAYBACK_RESTART。只取一个字节的 HTTP 探测和短时真实解码，不写播放进度报告。测试最后请求清理转码时服务器返回 404；三个候选都是直连，无待清理转码，不能将其当作播放失败。

单测覆盖服务器签发链接、直接跨域凭据清除、HTTPS 降级、签名查询逐字保留、CDN 后续跳转不能恢复信任及认证头、外挂字幕下载。另补齐原生 END_FILE 错误码、候选序号和最终失败的安全日志；诊断编号只进结构化错误与日志，界面仅显示短错误代码。

新增 `scripts/test-native-overlay.ps1`：用本地样片、隔离内存账号和报告处理器，通过正式 PlaybackLauncher → Shell → PlayerOverlay → VideoSurface，创建生产参数的 1×1 / audio=true libmpv。它验证实际 Playing、2228×1218 交换链与视口一致、真实按钮暂停/恢复、跳转、关闭、解绑、Stopped/发件箱及正常进程退出；不读取真实账号。Debug 与 AOT 都通过，进程正常退出、没有强制清理。此样片的 current-ao 未返回有效输出，本轮不作为声音或人工显示观感验收。

真实服务器的网络 / 解码复现与隔离的正式界面验证是两类证据，不合称为人工验收。修复后的 AOT 构建再次通过了完整界面回归：页面、主题、播放控制、全屏、50 次假播放关闭和关闭确认路径。
