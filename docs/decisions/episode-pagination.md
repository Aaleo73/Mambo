# 长篇剧集完整分页

日期：2026-10-06。

## 问题

用户反馈播放长篇剧集时，选集列表只能看到第 200 集。原播放目标解析和连播计划只请求 `StartIndex=0` 一次，即使服务器声明还有条目也不继续读取；服务器将单次返回限制为 200 条时可复现。连播计划另有 `Take(500)`，整剧和季的回退目标也分别只查询前 500 / 300 条。详情页在 NextUp 为空时存在相同截断。

## 修正

- Core 内的 `EmbyEpisodeReader` 共用于播放目标、连播计划和详情页 NextUp 回退。每页请求最多 500 条，按返回的原始条数推进偏移，总集数不设固定上限；过滤、排序和去重在读取后执行。
- 返回总数时读到总数；未返回总数时继续探测到空页。短页可能是服务器主动限制页大小，不能因此提前结束。
- 后续页没有新增有效 ID 时终止，防止服务器忽略 StartIndex 导致无限请求；若服务器仍声明有未读项，则视为不完整响应。中途空页、无效数量和网络失败也不发布残缺的完整计划，沿用原来的单集播放回退。
- 保留选中集的最新标题、续播位置和季内索引。每页均可取消，并跟随账号生命周期取消。请求仍只读取精简剧集字段，不获取 MediaSources。
- 详情页的横向剧集浏览继续使用原来的 30 条增量加载；播放器从完整计划投影选集列表。Contracts、XAML 和播放器内部接口均不变。

读取整季会增加长篇剧集首次准备时的元数据请求数：1001 集、服务器每页 200 条且提供总数时共 6 页；不提供总数时多一次空页探测。未改为后台增量追加，以保持当前选集、上一集/下一集及外置播放器使用一致的完整计划。

## 验证

修复前，新增长剧回归用例复现了第 200 集截断、超过 500 集的目标缺失，以及忽略后续页失败的问题。自动验证覆盖 1001 集、200 / 500 条服务器分页、有无总数、第 801 集定位、续播优先级、原始偏移和去重、分页中断与取消、详情页分页及播放会话跨第 200 集的下一集和超过 500 集的跳集。

- `dotnet build -p:Platform=x64`：0 警告、0 错误。
- 播放准备专项：32 / 32 通过。
- 最终 `dotnet test --no-build`：共 609 项，586 通过、23 项既有 GPU / 性能测量用例按配置跳过，0 失败；新增 18 项回归全部通过。
- 首次全套运行因旧排序测试的单页桩每次生成新 ID 且不声明总数而持续返回“新页”，已终止该测试进程，并为该固定五条数据的桩补充准确总数。真实分页逻辑未因此放宽，修正后专项和完整回归均通过。
