# 资料库筛选响应优化

日期：2026-10-05。针对用户反馈的筛选慢、卡住、点击无反应。

## 原因

- 兼容忽略筛选参数的服务器时，旧实现按 UI 页大小（60 条）重复扫描。每次换条件都会从头走 HTTP 分页，稀疏匹配尤其慢。
- 筛选选项接口失败后的扫描要全部结束才发布选项，已加载卡片的元数据也没有及时反映到筛选面板。
- 等待新条件时保留旧网格，却没有进行中的状态；连续点击立即创建多个请求和偏好写入。
- 年代只展开成当前已知的年份；旧偏好和大小写不同的类型可能与面板选中态不一致。

## 实现

- 保留服务器正常筛选的快速路径。收到不符合条件的条目后，才记住该账号、该资料库需要本地校验。
- 切换为不带筛选条件的共享扫描，每批最多 500 条。部分支持参数的服务器必须从无条件游标 0 重新开始，已显示条目按 ID 去重。
- 扫描保留可显示卡片所需的元数据，不下载图片。按账号、资料库、排序字段、排序方向隔离，最多保留 8 个扫描，5 分钟后新查询重新建立。完成的批次可跨条件复用；取消不发布迟到结果，也不抹掉已完成的批次。
- 筛选选项接口不可用时，共用默认排序的扫描，并逐批发布类型、年代、分级。手动刷新资料库、播放停止以及切换账号使相应缓存失效。
- 切换条件立即更新选中态和等待状态，连续点击在 200ms 内合并；取消恢复当前已显示结果对应的条件。失败保留旧结果并提供重试。新查询开始时暂停旧网格的自动翻页。
- 已加载卡片、服务器选项、已保存条件合并显示，增量更新保留已有 chip 对象。年代始终展开为完整十年，读取旧偏好时同样修正；类型和分级忽略大小写。
- 前端仅使用 Contracts，未新增前端对 Core 实现的引用；新 XAML 仍在 App 内，绑定使用 x:Bind。
